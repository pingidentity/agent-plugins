# Multi-factor Authentication Use Cases

## Overview
This area catalogs solution guides for applying MFA across Ping Identity products and integrations. It helps teams find guidance for protecting applications, VPN access, federated services, and APIs.

## Core Concepts
- **MFA:** Uses two or more distinct identity proofs to help confirm users are who they claim to be.
- **PingID integrations:** Apply MFA to web applications, VPNs, SSO, and offline authentication.
- **Web sessions:** PingFederate and PingAccess can coordinate sessions through PingID for web-application MFA.
- **Offline authentication:** Addresses MFA when PingID infrastructure cannot be reached, including during a network outage.
- **Federation and account linking:** Guidance covers AWS end-user API authentication through PingFederate token exchange and Amazon Alexa account linking through PingOne.

## When to use
- Use this area when planning MFA for web applications, VPN access, offline operation, SSO, or related integrations.
- Use it to locate guidance for Amazon Alexa account linking or AWS CLI federation and token exchange.

## When not to use
- This catalog is not an implementation procedure; use the linked solution guide for the selected scenario.
- It does not establish prerequisites, deployment limitations, or product-selection rules; consult product-specific documentation.
