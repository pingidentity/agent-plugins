# Single Sign-on Use Cases

## Overview
Single Sign-on Use Cases indexes solution guides for connecting Ping products with applications, identity repositories, and external platforms. It helps customers choose relevant SSO, federation, provisioning, authentication, and session-management patterns.

## Core Concepts
- **Federation:** SAML 2.0 and WS-Federation connect identity providers, service providers, and applications.
- **SSO patterns:** Service-provider-initiated, Active Directory, Workday, Exchange OWA, Salesforce, and 1Password scenarios support application access through established identities.
- **Provisioning:** SCIM integrations with Uber for Business and AWS IAM Identity Center support account lifecycle exchange.
- **Identity repositories:** PingFederate Bridge, PingDirectory, Active Directory, Salesforce, and SailPoint IdentityIQ participate in listed integrations.
- **Security and sessions:** Request signing, PingID MFA, device registration, session extension, and revocation address trust and access control.

## When to use
- Use this index when planning SSO or federation with enterprise or SaaS applications.
- Use it when provisioning, device registration, or session control is also required.

## When not to use
- Use the linked guide, rather than this index, for scenario-specific configuration.
- Use product-specific documentation for requirements outside the listed integration cases.
