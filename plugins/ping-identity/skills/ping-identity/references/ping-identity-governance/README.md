# Ping Identity Governance

## Overview
Ping Identity Governance governs user and application access through requests, approvals, certifications, and policy controls. It gives customers accountable processes for granting, reviewing, and resolving access decisions.

## Core Concepts
- **Access requests** let requesters seek roles, attributes, entitlements, bundles, or disconnected-system access through controlled approval and fulfillment.
- **Approval workflows** support sequential or concurrent decisions, automatic approval, and custom workflows while recording unsuccessful outcomes.
- **Access certifications** let designated certifiers assess attributes, entitlements, or application access and certify, revoke, or abstain.
- **Separation-of-duty policies** identify conflicting combinations of attributes, roles, or assignments and support remediation or justified, time-limited exceptions.
- **REST APIs** provide JSON-based communication with the platform and its components for governance integrations.

## When to use
- Use for governed access intake, approval, fulfillment, and removal.
- Use for recurring certification campaigns and accountable review decisions.
- Use to detect and resolve policy conflicts.

## When not to use
- For identity lifecycle or directory administration, use identity-management documentation.
- For connector or application onboarding, use the relevant onboarding documentation.
- For campaign, policy, request, or approval setup, use the Administration Guide.
