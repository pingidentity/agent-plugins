# Customer Use Cases

## Overview
Customer Use Cases is a catalog of implementation paths across Ping products and integrations. It helps organizations match common customer-identity outcomes—such as sign-on, application access, account recovery, and data synchronization—to a relevant use case.

## Core Concepts
- Social-provider authentication with PingOne or PingFederate supports federated sign-in scenarios.
- Sign-on-window customization in PingFederate or PingOne supports branded sign-on experiences.
- MFA policies for PingOne applications support stronger application authentication.
- Logging-data retrieval from PingOne supports access to operational log information.
- PingAccess agent integration and OAuth/OIDC application creation address protected applications and application connectivity.
- Password recovery, reset, and self-service features, plus PingDataSync connections between Active Directory or PingDirectory and PingOne, address account management and directory synchronization.

## When to use
- Use this area to identify a product-specific path for a common customer-identity scenario.
- Use it when comparing sign-on, application integration, self-service, or synchronization use cases.

## When not to use
- Do not use it as a complete implementation guide; use the product-specific documentation for configuration details.
- Do not infer capabilities outside the Ping product and integration context named by a use case.
